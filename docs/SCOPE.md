## 2. 硬件适用范围：只验证过一种组合

**已实测（唯一验证过的组合）**

| 项目 | 具体型号 |
|---|---|
| 开发板 | 江协科技 51 开发板（B 站教学视频配套的那块） |
| 主控 | **STC89C52RC / LE52RC** |
| USB 转串口 | **CH340**（板载，`1a86:7523`，芯片版本 `0x31`） |
| 手机 | OPPO PEPM00 / Android 13 / arm64-v8a / 无 root |

**未做任何验证，不要假定可用**

- **STM32 及任何 ARM Cortex-M 单片机**：完全没有试验过。
  本项目与 STM32 的烧录方式（SWD/JTAG/DFU/bootloader）毫无关系，
  `stcgal` 也不支持 STM32。**请勿用本方案去烧 STM32。**
- 其他 8051 系列：STC12 / STC15 / STC8 等，虽然 `stcgal` 支持，
  但本项目没有在这些芯片上测试过，`-P stc89` 协议参数也不适用于它们。
- 其他 USB 转串口芯片：CH341、CH9102、CP2102、PL2303、FT232 等均未验证
  （代码里写死了 `1a86:7523`）。
- 其他手机 / Android 版本 / 其他开发板厂商，均未验证。

## 3. 功能与性能限制

- **传输波特率被限制在 2400**（原因见
  [README · 设计决策 2](../README.md#2-为什么传输波特率锁死-2400)）。
  118 字节左右的固件约需 2 秒；大固件会慢。
- **必须人工冷启动**：STC89 只在上电瞬间进入 ISP，按复位键无效，脚本无法代替你断电。
- **需要给 pyserial 打补丁**，属于对依赖的本地修改。
- **需要给 SDCC 做跨 libc 处理**（`patchelf` + `glibc-runner`），且必须处理整个目录的
  ELF 可执行文件。
- 已知缺陷：`MAX_BPS` 会把 57600/115200 静默截断为 46875 baud，
  详见 [docs/DEBUG_LOG.md #14](DEBUG_LOG.md)。
